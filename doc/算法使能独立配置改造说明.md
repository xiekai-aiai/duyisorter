# 算法使能按「次 × 前后视」独立配置改造说明

> 基准版本：`bcaf513`（增大辅助吹气时间,辅配延迟）
> 改造目标：算法使能从「整机一维 / 分层二维」升级为「层 × 识别组 × 算法」三维独立配置，并修复改造过程中引入的崩溃、勾选失效、中文不生效等问题，同时完善打包/升级脚本对生产数据库的保护。

## 一、背景与核心概念

旧版算法使能只有一个一维数组 `nArithmeticEnable[ARITHMETIC_TOTAL]`（整机所有相机共享一套），以及一个分层二维数组 `nArithmeticEnableLevel[MAX_LEVEL][ARITHMETIC_TOTAL]`（仅茶叶机型按分选舱区分）。这两套粒度都无法表达「同一层内，不同识别组（次 × 前后视）启用不同算法」的需求。

### 关键概念

| 概念 | 含义 | 相关常量/字段 |
|---|---|---|
| 层 level | 物理分选舱 | `MAX_LEVEL = 3`，CF 机型只用 level 0 |
| 次 pass | 同一层内的工作流分段，**非硬常量，由通道分配决定** | —— |
| 前后视 | 每个次包含前视 / 后视两个视角 | 编码 0=前视，1=后视 |
| 识别组 groupId | = 次 × 2 + 前后视 | `MAX_GROUP_IDTNTIFY = 16` |
| 通道 unit | 物理相机地址 | `struLevelInfo[level].nUnitId[]` |
| 算法 arith | 单色1/差分/智能A 等算法种类 | `ARITHMETIC_TOTAL = 30` |

**groupId 编码规则：**

```
group 0 = 第1次前视    group 1 = 第1次后视
group 2 = 第2次前视    group 3 = 第2次后视
group 4 = 第3次前视    group 5 = 第3次后视
...（最多 16 组）
```

### 四种参数组合模式（`nMatAssembleMode`）

枚举定义见 [globalparams.h](file:///Users/thinklic/Desktop/duyisorter/src/globalparams.h#L337-L343)：

| 枚举 | 值 | UI 文案 | 同步规则 |
|---|---|---|---|
| `PARAMS_ALL_SEPARATE` | 1 | 全部单独设置 | 每个识别组完全独立 |
| `PARAMS_ALL_SAME` | 2 | 全部相同 | 所有组共用 group 0 的参数 |
| `PARAMS_FRONT_REAR_SAME` | 3 | 前后视相同 | 同一次内前/后视共用前视组：`groupId & ~1` |
| `PARAMS_FIRST_SECOND_SAME` | 4 | 前视相同后视相同 | 所有前视共用 group 0，所有后视共用 group 1：`groupId % 2` |

> 文案变更：`PARAMS_FIRST_SECOND_SAME` 旧文案「一二次相同」语义不准确，已改为「前视相同后视相同」。

## 三、核心功能改造：算法使能三维化

### 3.1 数据结构（globalparams.h）

在 `struCnfProfile` 中新增三维数组，运行时一律使用它；旧的一维/二维数组保留仅用于兼容旧方案文件读取：

```cpp
int nArithmeticEnable[ARITHMETIC_TOTAL];                       // 旧：整机一维（兼容读取）
int nArithmeticEnableLevel[MAX_LEVEL][ARITHMETIC_TOTAL];       // 旧：分层二维（兼容读取）
int nArithmeticEnableGroup[MAX_LEVEL][MAX_GROUP_IDTNTIFY][ARITHMETIC_TOTAL]; // 新：运行时主用
```

### 3.2 统一访问函数 getArithEnable()（globalflow.cpp）

所有运行时判断**不直接读三维数组**，而是通过该函数，由它根据当前组合模式实时返回正确组的值：

```cpp
int GlobalFlow::getArithEnable(int level, int groupId, int arith)
{
    if (level < 0 || level >= MAX_LEVEL) return 0;
    if (groupId < 0 || groupId >= MAX_GROUP_IDTNTIFY) return 0;
    if (arith < 0 || arith >= ARITHMETIC_TOTAL) return 0;

    int mode = struCnfp.nMatAssembleMode;
    switch (mode) {
    case PARAMS_ALL_SAME:
        return struCnfp.nArithmeticEnableGroup[level][0][arith];
    case PARAMS_FRONT_REAR_SAME:
        return struCnfp.nArithmeticEnableGroup[level][groupId & ~1][arith];
    case PARAMS_FIRST_SECOND_SAME:
        return struCnfp.nArithmeticEnableGroup[level][groupId % 2][arith];
    case PARAMS_ALL_SEPARATE:
    default:
        return struCnfp.nArithmeticEnableGroup[level][groupId][arith];
    }
}
```

### 3.3 下发逻辑 resetArithmeticEnable()（globalflow.cpp）

旧逻辑在层循环外算好**一张位图**，所有相机共用。新逻辑改为**遍历每个相机通道 → 算出它所属的 groupId → 用 `getArithEnable()` 取该组独立位图 → 逐相机下发**：

```cpp
for (i = 0; i < struCnfg.nLevelTotal; i++) {
    for (j = 0; j < struCnfg.struLevelInfo[i].nUnitLevelTotal; j++) {
        nUnitAddr = struCnfg.struLevelInfo[i].nUnitId[j];
        nGroupID  = getIdentifyGroupID(nUnitAddr, 0);
        if (nGroupID < 0 || nGroupID >= MAX_GROUP_IDTNTIFY) continue;

        int ae[ARITHMETIC_TOTAL];
        for (int k = 0; k < ARITHMETIC_TOTAL; k++)
            ae[k] = getArithEnable(i, nGroupID, k);

        // 用 ae[] 拼 sParam1 / sParam2 / sParam3 三张位图（位定义与旧版完全一致）
        ...
        // 智能 A/B/C/D 模型缺省时按位屏蔽
        ...
        MySerial.com1Write(CMD_UNIT_ARITHMETIC_ENABLE, UNIT, i, nUnitAddr,
                           0, 0, sParam3, sParam2, sParam1, 3);
    }
}
```

> 位图字节拼装顺序（sParam1/2/3 各 bit 对应的算法）保持与旧版一致，仅数据来源从「整层一张图」变为「每组一张图」。

### 3.4 方案文件读写（paramsprofile.cpp）

新增三维 key，读取时采用 **三维 → 二维 → 一维** 三层 fallback，保证旧版本方案文件可正常加载：

- 新 key：`3-40-<level>-<group>-<arith>`
- 旧二维 key：`3-38-<level>-<arith>`
- 旧一维 key：`3-11-<arith>`

```cpp
for (int lv = 0; lv < MAX_LEVEL; lv++)              // 注意: 用 MAX_LEVEL, 不能用 nLevelTotal
    for (int g = 0; g < MAX_GROUP_IDTNTIFY; g++)    // 注意: 用 MAX_GROUP_IDTNTIFY, 不能用 nIdentifyGroupTotal
        for (int a = 0; a < ARITHMETIC_TOTAL; a++) {
            QString key3d = QString("3-40-%1-%2-%3").arg(lv).arg(g).arg(a);
            QString key2d = QString("3-38-%1-%2").arg(lv).arg(a);
            QString key1d = QString("3-11-%1").arg(a);

            int def = struCnfp.nArithmeticEnableLevel[lv][a];
            if (def == 0) def = struCnfp.nArithmeticEnable[a];

            int v = setting.value(key3d, -1).toInt();
            if (v == -1)
                v = setting.value(key2d, setting.value(key1d, def).toInt()).toInt();

            struCnfp.nArithmeticEnableGroup[lv][g][a] = v;
        }
```

写入（保存方案）时循环范围与读取严格一致（`MAX_LEVEL × MAX_GROUP_IDTNTIFY`），只落三维 key，且仅在与备份值不同时写入：

```cpp
for (int lv = 0; lv < MAX_LEVEL; lv++)
    for (int g = 0; g < MAX_GROUP_IDTNTIFY; g++)
        for (int a = 0; a < ARITHMETIC_TOTAL; a++)
            if (struCnfp.nArithmeticEnableGroup[lv][g][a]
                != _t_struCnfp.nArithmeticEnableGroup[lv][g][a])
                setting.setValue(QString("3-40-%1-%2-%3").arg(lv).arg(g).arg(a),
                                 struCnfp.nArithmeticEnableGroup[lv][g][a]);
```

> **重要：读、写循环的 level 维与 group 维都必须用硬常量 `MAX_LEVEL` / `MAX_GROUP_IDTNTIFY`，不能用 `struCnfg.nLevelTotal` 或 `struLevelInfo[lv].nIdentifyGroupTotal`。**
>
> 因为 `getProfileSetting()` 在 `initAll()` 的 `getProfile()` 阶段就执行，而机型层级信息（`getLevelInfo_*()` 设置的 `nLevelTotal` 与每个 `nIdentifyGroupTotal`）要到其后的 `initMachineType()` 才初始化——此刻这两个字段仍是 0。
>
> - 若读取循环用这两个字段做上界，循环体一次都不执行，`nArithmeticEnableGroup` 保持全 0。此时表现为：界面里勾选、保存都「看似正常」（保存发生在机型初始化之后），但**重启或重新加载方案后，已保存的算法勾选全部丢失**。
> - 同文件旧的二维 `3-38` 读取循环本来就用 `MAX_LEVEL`，新代码必须沿用这一做法。
> - 多读出来的多余 level/group 在方案文件中没有对应 key，会走 fallback 得到默认值，数组访问始终有界、不会越界；保存时它们与备份值相同也不会产生多余写入。

## 四、改造引入问题的修复（关键）

### 4.1 启动 Segfault（递归信号冒泡）

**现象：** 进入算法设置页面构造 `MainWidget` 时段错误（exit 139）。

**根因：** `updatePage()` 与 `updateMatModeCombo()` 中的 `setCurrentIndex()` 未屏蔽信号，形成递归：

```
updatePage()
 └─ tabBar->setCurrentIndex(0)          // 触发 currentChanged → changeCurrentSlt（排队）
 └─ updateMatModeCombo()
      └─ matModeCombo->setCurrentIndex(1)
           └─ 触发 setMatModeCombo()
                └─ updatePage()         // 递归回来
                     └─ ... 递归过程中 arithmeticBtn / arithmeticBox 的 QVector 被重建
                          └─ 排队的 changeCurrentSlt 执行时访问已失效对象 → 崩溃
```

**修复：** 对两处 `setCurrentIndex()` 加 `QSignalBlocker`：

- `matModeCombo->setCurrentIndex(index)` 前屏蔽 `matModeCombo`
- `tabBar->setCurrentIndex(0)` 前屏蔽 `tabBar`

### 4.2 算法 checkbox 无法勾选 / 按钮灰色

根因有两处，均已修复：

**(1) `updatePage()` 屏蔽 tabBar 信号后漏刷新算法列表**

`QSignalBlocker` 会让 `currentChanged → changeCurrentSlt() → updateArithmeticList()` 这条链不触发，导致勾选框状态不恢复。修复为在 `updatePage()` 末尾手动补一次：

```cpp
void PageIdentify::updatePage()
{
    updateTabBar(tabBar, false, true);
    {
        QSignalBlocker blocker(tabBar);
        tabBar->setCurrentIndex(0);
    }
    updateMatModeCombo(m_nMatMode);
    updateArithmeticList();   // 手动补刷新
}
```

**(2) setArithButton() 西瓜子互斥条件漏 group 下标（致命）**

数组升维后，下面这一行漏改，仍按二维访问：

```cpp
// 错误：ARITH_WATERMELON 被当成了 group 下标，读到错误内存
if (m_nArithmeticEnable[struGsh.nLevel][ARITH_WATERMELON] == 0 ...)

// 正确：补 [tabBar->currentIndex()]
if (m_nArithmeticEnable[struGsh.nLevel][tabBar->currentIndex()][ARITH_WATERMELON] == 0 ...)
```

错误下标会读到不可预期的非 0 值，使普通算法（如单色1）误走进「西瓜子互斥」分支，一次性把当前页所有勾选框 `setEnabled(false)`，表现为「第一次能勾上、第二次起点击无反应、按钮灰色」。

此外 `updateArithmeticState()` 中原有的 `struCnfp.nArithmeticEnable[ARITH_PISTACHIO] == 0;` 是比较表达式而非赋值（笔误），已修正为对三维内存的真正赋值 `= 0`。

### 4.3 x86_64 Debug 中文不生效

两层原因：

1. **语言目录宏在 x86_64 下落到板卡路径**，shadow build 与源码目录里都找不到 `.qm`。在 [globalparams.h](file:///Users/thinklic/Desktop/duyisorter/src/globalparams.h#L543-L552) 为 x86_64 单独指定路径：

```cpp

#elif defined(__x86_64__)

#else
#define LANG_DIR  APP_PATH "/i18n/"                  // aarch64 板卡
#endif
```

2. **改了 `.ts` 但没重新编译 `.qm`**。运行时加载的是旧 `zh-cn.qm`。需在 VM 执行：


## 八、注意事项

1. **所有运行时判断统一走 `getArithEnable(level, groupId, arith)`**，不要直接读 `nArithmeticEnableGroup`，否则在「全部相同 / 前后视相同」等共享模式下会读到非权威组的值。
2. **方案读写中遍历三维数组时，level 维用 `MAX_LEVEL`、group 维用 `MAX_GROUP_IDTNTIFY`**，均为硬常量。在 `getProfile()` 读取阶段 `nLevelTotal` / `nIdentifyGroupTotal` 都尚未初始化（要等 `initMachineType()` 里的 `getLevelInfo_*()`），用它们会使读取循环整体跳过、方案勾选重启后丢失。
3. **方案文件向后兼容**：旧方案没有 `3-40` key 时自动回退到 `3-38` / `3-11`，无需迁移；保存后会升级为三维 key。
4. **位图下发按相机独立计算**，不可所有相机共用一张位图。
5. **`.ts` 改动后必须 `lrelease`**；UI 初始化路径上的 `setCurrentIndex()` 必须用 `QSignalBlocker` 包裹，且屏蔽信号后要手动补一次依赖该信号的刷新函数。
