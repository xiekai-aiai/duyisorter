现在最重要的结论

你的环境是：

ARMv7
+
glibc 2.18
+
GCC 9.1

这是一个相对老的 Linux ABI。

因此：

不能直接拿现代 Ubuntu 上的 ARM wheel 或 PyInstaller 包部署。

例如现代 ARM Linux wheel 很可能要求：

GLIBC_2.28
GLIBC_2.27
GLIBC_2.25

而你的设备只有：

GLIBC_2.18

所以后面必须以你的：

SigmaStar Toolchain Sysroot

为基准构建。

我建议的部署方案调整

现在我不建议走：

Python ARM
 ↓
pip install numpy
 ↓
pip install scikit-learn

因为 pip 很可能拿到：

manylinux2014_armv7l

或者：

manylinux_2_28

存在 ABI 风险。

更稳的路线：

Ubuntu x86
    │
    │ SigmaStar GCC
    │
    ▼
ARM Python
    │
    ├── NumPy
    │
    ├── scikit-learn
    │
    └── PyInstaller
          │
          ▼
      ARM Board
      glibc 2.18
但是先做一个最小验证

先编译：

cd /home/a64

cat > hello.c << 'EOF'
#include <stdio.h>

int main(void)
{
    printf("Hello ARM!\n");
    return 0;
}
EOF

arm-linux-gnueabihf-gcc hello.c -o hello_arm

检查：

file hello_arm

应该类似：

hello_arm: ELF 32-bit LSB executable,
ARM,
EABI5 version 1 (SYSV),
dynamically linked,
interpreter /lib/ld-linux-armhf.so.3

然后：

readelf -l hello_arm | grep interpreter

应该：

Requesting program interpreter: /lib/ld-linux-armhf.so.3

检查依赖：

readelf -d hello_arm | grep NEEDED

应该：

Shared library: [libc.so.6]
QEMU 验证

安装：

apt update
apt install -y qemu-user

然后：

qemu-arm -L "$SYSROOT" ./hello_arm

预期：

Hello ARM!

如果这里成功，说明：

交叉工具链      OK
sysroot        OK
ARM glibc      OK
QEMU           OK
动态链接器      OK

这样后面所有工作都有基础了。
